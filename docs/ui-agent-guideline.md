# UI Agent Guideline

이 문서는 Joonsik 계열 플래너/캐릭터 보상 앱을 만들 때 에이전트가 따라야 할 UI/렌더링 지침이다. 목표는 "대충 비슷한 느낌"이 아니라, 레이아웃과 디테일이 깨지지 않는 재현 가능한 구현이다.

## 1. Core Intent

- 사용자는 작은 데스크톱 앱 안에서 할 일, 진행률, 포인트, 캐릭터 피드백을 한눈에 확인해야 한다.
- UI는 귀엽고 정돈된 플래너 감성, compact density, 캐릭터 존재감, 명확한 보상 피드백을 동시에 유지한다.
- 기능 추가보다 시각적 안정성이 우선이다. 레이아웃이 흔들리면 기능이 완성돼도 실패로 본다.

## 2. Visual Contract

- Window/app frame은 고정된 카드형 데스크톱 앱처럼 보여야 한다. 가장자리 여백, 창 모서리, 내부 패널 간격을 임의로 늘리지 않는다.
- 큰 구획은 먼저 잠근 뒤 세부 컴포넌트를 배치한다. 새 요소는 기존 구획 안에 넣는다.
- 색상은 1개의 주 팔레트와 1~2개의 강조색만 사용한다. 보라 계열을 중심으로 쓰더라도 채도, 대비, 강조 범위를 통제한다.
- 둥근 모서리, border, shadow, gradient 강도는 화면 전체에서 같은 문법을 사용한다. 한 영역만 다른 앱처럼 보이면 안 된다.
- 아이콘, 캐릭터, 버튼, 카드의 선 두께와 대비가 서로 맞아야 한다.
- 텍스트는 작아도 읽혀야 한다. 장식 폰트를 본문에 과하게 쓰지 않는다.

## 3. Layout Lock

- 핵심 레이아웃은 navigation/sidebar, main task canvas, progress/point cards, memo/history cards, bottom character/chat area를 기준으로 한다.
- 완료/미완료 할 일, 진행률, 포인트, 메모, 최근 기록 같은 정보 그룹은 카드 단위로 분리하되, 같은 행/열 리듬을 유지한다.
- 수치형 정보는 카드 중앙 또는 우측 정렬 기준을 명확히 맞춘다. 진행률 원형/바형 UI는 기준선이 흐트러지면 안 된다.
- 하단 캐릭터 영역은 "덧붙인 채팅창"이 아니라 앱의 감정 피드백 영역이다. 캐릭터, 말풍선, 입력창의 관계를 유지한다.
- 반응형 조정은 허용하되, 작은 폭에서 카드가 무작위로 밀리거나 겹치면 안 된다.

## 4. Rendering Rules

- 캐릭터/픽셀 아트는 `image-rendering: pixelated` 또는 `crisp-edges` 중 하나를 명확히 지정한다.
- SVG/이미지는 원본 비율을 유지한다. 임의 stretch, blur, crop으로 얼굴/실루엣이 변형되면 안 된다.
- 그림자와 blur는 과하게 쓰지 않는다. 부드러운 UI라면 1~2단 shadow, 픽셀 UI라면 hard shadow로 통일한다.
- 애니메이션은 상태 이해를 돕는 정도로만 사용한다. 보상 reveal, 버튼 press, hover, progress update가 주요 대상이다.
- 모든 움직임은 레이아웃 재계산으로 흔들리지 않게 `transform`/`opacity` 중심으로 구현한다.

## 5. Agent Question Protocol

에이전트는 다음 상황에서 반드시 작업을 멈추고 사용자에게 질문해야 한다.

- 레퍼런스 이미지와 기존 코드/문서의 디자인 방향이 충돌할 때
- "비슷하게", "예쁘게", "깔끔하게"처럼 해석 폭이 큰 요청만 있을 때
- 레이아웃 구획, 화면 폭, 캐릭터 크기, 컬러 팔레트를 바꿔야 할 것처럼 보일 때
- 기능 요구가 UI 락을 깨뜨릴 가능성이 있을 때
- 구현 후 스크린샷이 기준 이미지와 다르게 보이는데 원인이 명확하지 않을 때

질문은 한 번으로 끝내지 않는다. 요구가 여전히 모호하면 다음 결정을 나누어 여러 번 확인한다: `레이아웃 유지 여부`, `톤 우선순위`, `허용 가능한 변경 범위`, `레퍼런스 중 더 중요한 화면`, `검증 방식`.

## 6. Required Verification

- 구현 전 기준 스크린샷 또는 레퍼런스 이미지를 확인한다.
- 구현 후 같은 viewport에서 스크린샷을 찍고, 레이아웃/간격/색/캐릭터 비율을 비교한다.
- 콘솔 에러와 빌드/린트를 확인한다.
- 사용자가 "디자인 디테일이 다르다", "레이아웃이 깨졌다"고 느낄 수 있는 차이가 있으면 완료 보고 전에 먼저 알린다.

## 7. Done Criteria

- 큰 구획, 카드 위치, 하단 캐릭터 영역이 기준과 같은 역할로 보인다.
- 색상, radius, shadow, font, icon density가 한 디자인 시스템으로 읽힌다.
- 캐릭터와 대화 영역이 흐릿하거나 찌그러지지 않는다.
- 기능 추가 후에도 초기 화면의 균형과 정보 밀도가 유지된다.
- 에이전트가 임의 판단한 부분은 문서화되었고, 중요한 판단은 사용자에게 질문했다.
